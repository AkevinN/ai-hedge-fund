# AI Hedge Fund 系统迭代开发计划（优化版）

## 1. 项目概述

本迭代开发计划旨在实现AI Hedge Fund系统的五大核心功能模块，包括国内数据系统接入、量化预测系统增强、通信与信息管理系统、长期记忆系统和方案验证系统。采用模块化设计和敏捷开发模式，确保各功能模块间低耦合高内聚，可独立交付和扩展。

### 1.1 与现有系统的集成关系

本计划基于现有 ai-hedge-fund 项目进行扩展，主要集成点：

| 现有模块 | 扩展方向 | 集成方式 | 涉及文件 |
|----------|----------|----------|----------|
| `src/agents/` | 增强分析师Agent能力，新增国内市场分析能力 | 扩展现有Agent，新增国内市场分析工具 | `src/agents/*.py` |
| `src/tools/api.py` | 接入国内数据源，扩展数据获取能力 | 新增国内数据适配器，复用现有缓存机制 | `src/tools/api.py` |
| `src/graph/` | 增强工作流编排，支持预测和验证节点 | 扩展StateGraph，新增预测和验证节点 | `src/graph/state.py` |
| `app/backend/routes/` | 新增服务模块，扩展API接口 | 遵循现有FastAPI架构，新增数据、预测、通信等路由 | `app/backend/routes/*.py` |
| `app/backend/services/` | 新增业务逻辑服务 | 新增数据、预测、通信、记忆、验证等服务 | `app/backend/services/` |
| `app/backend/database/` | 扩展数据库模型，支持国内金融数据 | 扩展现有SQLAlchemy模型，新增国内金融数据模型 | `app/backend/database/models.py` |
| `app/frontend/src/components/` | 增强可视化，支持国内市场数据分析 | 扩展React Flow组件，新增国内数据可视化组件 | `app/frontend/src/components/` |
| `app/frontend/src/nodes/` | 新增国内市场分析节点 | 扩展现有节点组件，新增国内数据节点 | `app/frontend/src/nodes/` |

### 1.2 系统架构演进

## 2. 迭代开发策略

- **迭代周期**: 3周/迭代（压缩周期，提高交付频率）
- **开发模式**: 敏捷开发，每周进行一次迭代评审
- **项目管理工具**: Git + GitHub Issues
- **文档体系**: 需求文档、设计文档、接口文档、测试文档
- **持续集成**: GitHub Actions + pytest
- **并行开发**: 数据模块与验证模块可并行推进
- **代码规范**: 遵循现有项目规范（Python: Black + Flake8 + mypy; TypeScript: ESLint + Prettier）

### 2.1 MVP定义（最小可行产品）

为降低风险，定义三个MVP里程碑：

| MVP阶段 | 完成时间 | 核心能力 | 验证目标 |
|---------|----------|----------|----------|
| MVP1 | 第6周 | 国内数据获取 + 基础回测 | 能够获取A股数据并进行简单策略回测 |
| MVP2 | 第12周 | 量化预测 + 通信推送 | 能够生成预测信号并推送交易提醒 |
| MVP3 | 第18周 | 完整系统 + 长期记忆 | 全功能系统，支持策略学习和优化 |

### 2.2 开发流程

1. **需求分析与设计**: 每周一进行需求分析和设计评审
2. **编码实现**: 周二至周四进行编码开发
3. **测试验证**: 周五进行单元测试和集成测试
4. **迭代评审**: 每周五下午进行迭代评审，演示成果，规划下周任务
5. **文档更新**: 周末更新相关文档

### 8.2 关键风险应急预案

#### 8.2.1 数据源故障预案

- **触发条件**: 主要数据源（如akshare）连续失败超过3次
- **响应措施**: 
  1. 自动切换到备用数据源（如tushare）
  2. 启用本地缓存数据
  3. 发送告警通知运维团队
- **恢复策略**: 待主要数据源恢复后，自动切换回主要数据源，并同步数据

#### 8.2.2 大模型服务异常预案

- **触发条件**: LLM调用超时或返回异常
- **响应措施**: 
  1. 自动降级为传统ML模型预测
  2. 记录异常日志
  3. 发送告警通知AI团队
- **恢复策略**: 待大模型服务恢复后，自动切换回大模型，并验证结果一致性

#### 8.2.3 系统性能异常预案

- **触发条件**: 系统响应时间超过阈值（P99 > 5秒）
- **响应措施**: 
  1. 自动扩容服务实例
  2. 清理缓存，优化数据库查询
  3. 发送告警通知运维团队
- **恢复策略**: 待性能恢复正常后，分析性能瓶颈，进行针对性优化
